## Задача на ближайшие дни: push-уведомления на одно устройство от двух компаний

_Записано 15.08.2026 по вопросу владельца (у него две студии) — не начато, только
проанализировано._

**Проблема:** одно устройство сейчас физически может быть подписано на пуши только ОДНОЙ
компании одновременно. `push_subscriptions` в БД имеет `UNIQUE(endpoint)` — при каждом нажатии
«Включить» в Настройках строка перезаписывается на компанию, которая в этот момент активна
(`backend/src/platform/push.routes.js`, `ON CONFLICT (endpoint) DO UPDATE SET company_id = ...`).
Значит если владелец включает уведомления в Студии №1, а потом заходит в Студию №2 (то же
устройство) — Студия №2 никогда не пришлёт пуш, пока он явно не включит уведомления там, что
молча отключит Студию №1.

**Что нужно решить перед реализацией:**
1. Схема — либо убрать `UNIQUE(endpoint)` и держать по строке на пару (endpoint, company_id),
   либо завести отдельную join-таблицу устройство↔компании. Разные последствия для очистки
   протухших подписок (`sendPushToCompany`/`sendPushToSuperAdmins` в `core/pushNotify.js` сейчас
   удаляют строку по `id` при 404/410 от push-службы — при "одно устройство, много компаний"
   нужно удалять по `endpoint`, а не по одной строке, иначе очистка будет неполной).
2. UX — сейчас в уведомлении нигде не подписано, из какой компании оно пришло (не нужно было,
   когда подписка одна). Если разрешить обе — нужно решить, добавлять ли название компании в
   текст (например, префикс к заголовку "Студия №1: Заканчиваются расходники") — вероятно да,
   иначе непонятно, куда бежать.
3. Фронт — `frontend/src/utils/push.js` (`subscribeToPush`) и `Settings.jsx` (тумблер
   "Включено на этом устройстве") сейчас рассчитаны на одно состояние подписки на устройство,
   без понятия "по каким компаниям". UI тоже придётся менять — не просто вкл/выкл, а список
   компаний с отдельными тумблерами.

**Не начато** — при следующей сессии просто открыть этот раздел и продолжить с пункта 1.
