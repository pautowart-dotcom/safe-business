# Б1. Что ИИ-ассистент знает о компании клиента

13.10.2026. Только чтение кода, ничего не менял.

## Как устроено сейчас

На каждый вопрос сервер (`backend/src/modules/ai-assistant/ai-assistant.routes.js`):
1. Берёт профиль из теста безопасности и **только ниши** компании (`knowledge.js`, `buildKnowledgeContext`).
2. Ищет 2–3 подходящих пункта теста этих ниш (по основам слов, если не нашлось — короткий запрос к модели «выбери номера пунктов»).
3. Кладёт найденное в системное сообщение вместе со статусом пункта у компании: «НАРУШЕНИЕ» / «исправлено».
4. Модель (YandexGPT) пересказывает. Суммы и статьи — только из справки (правила в `systemPrompt.js`).

Плюс инструменты: записать визит, расход, доход, сводка финансов, статус безопасности.

## Что ИИ знает

| Данные | Откуда | Передаётся ИИ |
|---|---|---|
| Ниши компании (одна или несколько) | профиль теста | да |
| Нарушения по тесту: открыто / исправлено | результаты теста | да, только по найденным пунктам |
| Финансы, визиты | по запросу через инструмент | да, если спросили |
| Индекс безопасности, список нарушений | инструмент `get_security_status` | да, если спросили |
| Последние 8 сообщений диалога | фронт | да |

## Что в базе есть, но ИИ не получает

| Данные | Где лежит | Почему важно |
|---|---|---|
| **Форма: самозанятый / ИП / ООО** | `security_profiles.legal_form` — **уже загружается** в том же вызове, но не передаётся | ответ «нужна ли медкнижка», «нужна ли касса», штраф ИП или юрлица — зависит от формы |
| **Как работает: один / с сотрудниками / сдаёт места / смешанно** | `security_profiles.work_model` — **уже загружается**, не передаётся | половина вопросов про сотрудников зависит от этого («работаю одна — нужна ли медкнижка») |
| Регион | `companies.region_code` | вывеска, патент, местные штрафы |
| Налоговый режим | `companies.tax_regime` | касса, отчёты, патент |
| Есть ли сотрудники (отдельный флаг) | `companies.has_employees` | то же |
| Дата начала патента, его стоимость, дата регистрации ИП, дата последней СОУТ | `companies.*` | «когда платить», «когда продлевать» |
| Своё помещение есть / нет (универсальная ниша) | `security_profile_niches.has_premises` | загружается, не передаётся |
| «Мои сроки» (даты документов) | модуль сроков | «когда у меня кончается медкнижка» |
| История проверок, свои документы | модули безопасности | «что проверяли в прошлый раз» |

## Что не знает вовсе (нет нигде)

- Ответов на вопросы «как сделать правильно» — вывеска, чек коррекции, ОКВЭД и т.п. Это и есть карточки (блок А), подключим на Б3.
- Город внутри региона (для Москвы регион = город, для остальных правила благоустройства — по городу).

## Попутные находки

1. **Б5 уже наполовину сделан.** Когда у ИИ нет ответа, он ставит метку, вопрос сохраняется в таблицу `ai_unanswered_questions` (зашифрованно, без привязки к компании), а в админке есть список `/ai-unanswered`. Остаётся решить, как из этого списка рождаются карточки.
2. **Пункты теста не фильтруются по профилю.** ИИ ищет по всей матрице нарушений ниши, а не по тем пунктам, что показываются этой компании. Самозанятому мастеру без сотрудников ИИ может пересказать, например, пункт про СОУТ. Как именно тест отбирает пункты по форме и модели работы, не проверял — проверю на Б2 живыми вопросами.

## Что предлагаю (не делал)

Самое дешёвое и полезное — передавать ИИ одну строку о компании: «ИП, с сотрудниками, Москва, патент». Форма и модель работы уже загружаются в том же месте, регион и режим — один запрос к `companies`. Плюс правило в промпте: «если ответ зависит от формы, режима или сотрудников — отвечай для этой компании». Это небольшая правка, но по нашему правилу «не добавлять без спроса» — только с твоего «да». Логично сделать её вместе с Б3 (подключение карточек), потому что поле карточки `от_чего_зависит` как раз под эти данные.
