# Статус на 25.07.2026 — передача в новый чат

## Что сделано и подтверждено рабочим

- **Переименование поддоменов**: `app.business-safe.ru` / `admin.business-safe.ru` → `lk.business-safe.ru` / `office.business-safe.ru`. Причина: провайдерская блокировка в РФ (СНИ-уровень) конкретно этих двух имён — смена IP сервера не помогла, что подтвердило: дело в имени, не в IP. Новые имена работают.
- **SSL-сертификат**: после расширения сертификата под новые имена он "терялся" при повторном certbot-выпуске, т.к. попал в директорию `business-safe.ru-0001`, а `deploy/nginx.conf` в git указывал на путь без `-0001`. Поправлено и закоммичено — при следующих деплоях больше не откатится.
- **Баг: загруженные фото (аватар, визиты, документы) отдавали 404.** Причина: в nginx regex-локация кэширования статики (`*.jpg`/`*.png`/...) перехватывала `/api/uploads/*.jpg` раньше, чем `location /api/` (regex-локации в nginx приоритетнее префиксных без `^~`). Добавлен `^~` — **подтверждено фикс работает** (тестировал напрямую, было 404 → стало 200).
- **`backend/.env.production`**: `CORS_ORIGIN`/`FRONTEND_URL` указывали на голый IP по HTTP вместо домена — из-за этого могли быть неправильными, например, ссылки-приглашения. Поправлено на `https://lk.business-safe.ru`.
- **Проблема с доступом лично у владельца** (не блокировка сайта): на его личном устройстве в VPN-профилях выбран по умолчанию **v2RayTun** — пользователь решил просто пользоваться через VPN, дальше не разбирались.
- **Домен опробован end-to-end**: работает у сторонних пользователей (проверял реальными тестовыми аккаунтами Мастер/Администратор/Владелец в реальной компании владельца, оба его компании).

## Не решено — краш "Что-то пошло не так" / "n is not a function"

- Воспроизводится у владельца **стабильно и на любом устройстве** (его телефон, телефон жены, новый iPhone с новым аккаунтом) в разделах Дедлайны, Журналы (печатные бланки), Финансы, Безопасность, Ещё — "при любом нажатии".
- **НЕ воспроизводится** ни разу при экстенсивном тестировании: Chromium и WebKit (эмуляция iPhone), медленная сеть, быстрые клики/тапы, настоящий аккаунт владельца (реальный пароль, обе его компании), тестовые аккаунты всех ролей в его реальной компании.
- Технически (по декодированному sourcemap) краш происходит внутри `react-dom`, в месте, отвечающем за detach ref / effect cleanup при переходе между страницами — но точную строку в НАШЕМ коде не удалось определить (имена в sourcemap указывают только на `useAuth()`/`usePeriodParams()` call sites — судя по всему, это ближайшие по имени функции в scope, не буквальное место падения).
- **Проверено и исключено** как причина: блокировка РКН (домен не в реестре), iCloud Private Relay ("Частный узел" — недоступен для аккаунтов РФ), устаревший кэш браузера (новый iPhone с нуля тоже падает), Kaspersky/антивирус с HTTPS-инспекцией (пользователь: ничего не установлено, это iPhone), сама react/react-dom/react-router-dom версия (уже последние в линейке 18.x/6.x).
- **Применены defensive-фиксы** (не подтверждено, что это точная причина, но это реальные баги/риски, найденные чтением кода):
  1. Автоперезагрузка один раз при краше вместо ручной кнопки "Обновить" (`ErrorBoundary.jsx`, guard через sessionStorage от цикла).
  2. Защита `usePullToRefresh`/touch-обработчиков в `Layout.jsx` от обращения к уже отмонтированным refs при быстром переходе во время жеста.
  3. **Важный найденный баг**: `api/client.js` — при HTTP 401 каждый параллельный запрос на странице (их обычно несколько через `Promise.all`) независимо вызывал `window.location.href = '/login'` — жёсткий обрыв страницы браузером посреди того, как React ещё обрабатывает остальные ответы. Добавлен guard (редирект один раз, пропускается если уже на `/login`).
- **После всех трёх фиксов баг всё ещё воспроизводится** (владелец проверил) — причина пока не найдена.
- В коде включены **sourcemap** (`frontend/vite.config.js`, `build.sourcemap: true`) — следующий краш в логе будет читаться точнее.
- **Лог реальных ошибок**: office.business-safe.ru → раздел **"Логи краша"** (только Super Admin) — там видно `message`, `stack`, `componentStack`, `route`, `user_agent`, дату. Все собранные до сих пор логи — от `YaBrowser` (Windows) и Android; последний тест был на iPhone.

### Что стоит попробовать в новом чате (если возьмётесь копать дальше)
- У владельца ДВЕ компании на аккаунте (это единственное, что отличает его аккаунт от big тестовых, кроме собственно "он реальный пользователь") — переключение между ними тестировали, не воспроизвелось, но стоит перепроверить внимательнее.
- Возможно, стоит попросить владельца воспроизвести с открытым DevTools Console на **самом телефоне** (iOS Safari поддерживает удалённую отладку через Mac + кабель, "Web Inspector") — это даст 100% точный стек с реального устройства, а не приближение через Chromium/WebKit-эмуляцию.
