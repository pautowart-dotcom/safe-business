# Документы обновляются сами — как выпустить новую версию шаблона

22.10.2026. Механизм: `scripts/documentUpdates.js` (cron 7:30), `modules/document-templates/generate.js`,
миграция 0153, кнопка «Обновить» в «Безопасность» → документы.

## Когда выпускать
Изменился закон, на который опирается шаблон (например, новые Правила бытового обслуживания
вместо ПП № 1514 — тот действует до 01.01.2027; на 22.10.2026 новые правила только в проекте
Роспотребнадзора от 17.02.2026). Повод ловит `lawChangeMonitor.js` → очередь на подтверждение.
Выпускаем только после того, как акт **принят и опубликован**, не по проекту.

## Как выпустить (одна правка — обновятся все клиенты)
1. В файле шаблона (`modules/document-templates/content/templates/*.js`) поправить текст.
2. Увеличить `version` на 1.
3. Добавить запись в `changes` (массив; если его нет — создать):
   ```js
   changes: [
     { version: 2, date: '2027-01-01', note: 'Обновлено под новые Правила бытового обслуживания: …' },
   ],
   ```
   `note` — 1–2 предложения простыми словами, что изменилось для клиента. Это увидит клиент
   в уведомлении и рядом с документом. Без запугивания и обещаний.
4. Если добавили новое **обязательное** поле — автоматически документ не пересоберётся:
   клиент получит «нужно дозаполнить». Лучше делать новые поля необязательными.
5. Деплой. Дальше само:
   - подписка + купленные документы → пересборка из сохранённых данных, уведомление с push и Telegram;
   - без подписки → запись в «Уведомлениях» (без push) и отметка «Вышла новая версия» с кнопкой «Обновить».

## Что важно помнить
- Пересобирается только **последняя** версия каждого документа компании.
- Статус шаблона (`draft` / `reviewed` / `adapted`) переносится в новую версию как есть.
- Документ, уже подписанный клиентом на бумаге, сервис не заменяет — клиент сам скачивает новую
  версию и переподписывает. Текст уведомления говорит об этом прямо.
