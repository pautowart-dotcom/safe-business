# Раздел «Уведомления»: что уже есть и что предлагаю (Ж1)

14.10.2026, идея владельца: «раздел уведомлений — туда приходят и сроки, и изменения по законам, и сразу написано, как это коснётся владельца». Это предложение, ничего не построено.

## Что уже есть в коде

| Что | Где | Чего не хватает |
|---|---|---|
| Push на телефон / в браузер | `core/pushNotify.js`, тумблеры по категориям в Настройках | Push исчезает: прочитал и забыл, вернуться к нему негде |
| Напоминания о сроках: за 30, 14, 7, 1 день и в день срока | `scripts/deadlineReminders.js` | Только push. Сами сроки видны в «Центре действий», но истории «что мне напоминали» нет |
| Налоговые сроки по режиму | `core/taxDeadlines.js` | То же |
| Поиск изменений законов на официальном портале — только по нормам, на которые продукт уже ссылается | `scripts/lawChangeMonitor.js` → таблица `law_change_candidates` | Кандидаты ждут разбора в админке |
| Опубликованное объяснение изменения | таблица `law_change_notices` | **Один текст на всех.** Нет «как это касается вас»; видят только подписчики ИИ-тарифа |
| «В вашем тесте появились новые пункты» | `scripts/newFindingsNotifier.js` | Только push |
| Лента «что сервис сделал за вас» на главной | `platform/watch-feed.routes.js` | Последние 14 дней, это не входящие |

Вывод: сами события уже есть. Не хватает общего места, где они копятся, и текста под конкретного владельца.

## Что предлагаю

**1. Один раздел «Уведомления»** — входящие, как в почте: новое сверху, непрочитанное выделено. Три вида:
- **Срок** — «через 7 дней заканчивается медкнижка у Анны» → кнопка «Отметить, что продлили».
- **Изменился закон** — заголовок простыми словами + **«Что это значит для вас»** + «Что сделать» (или «Вам ничего делать не нужно»).
- **Новое в тесте** — «Появился пункт про стирку рабочей одежды — ответьте на один вопрос».

Push остаётся как сигнал: он ведёт в раздел, а не заменяет его.

**2. «Как это касается вас» — не ИИ на лету, а варианты по условиям.** Для каждого изменения пишем 2–4 коротких варианта по тому же полю «от чего зависит», что у карточек: есть ли сотрудники, режим налогов, регион, ниша. Система сама выбирает вариант по данным компании (строка «О компании» из Б1 уже это знает). Пример — выдуманный, только чтобы показать форму:

> **С 1 марта меняется форма отчёта о сотрудниках**
> *Если у вас есть сотрудники:* первый отчёт по новой форме — до 25 апреля. Через бухгалтерию в банке это делается автоматически, проверьте, что тариф обновлён.
> *Если сотрудников нет:* вас не касается.

Почему не ИИ на лету: если ИИ ошибётся в «вас это не касается», владелец пропустит срок — ровно то, от чего мы обещаем порядок. Варианты черновиком пишет Claude по первоисточнику, ты утверждаешь в админке (как сейчас с `law_change_notices`) — и после этого один текст уходит всем, к кому подходит условие.

**3. Если вариант к компании не подходит** (не хватает данных, например не указан режим) — честно: «Может касаться вас, если вы на УСН. Укажите режим в настройках — подскажем точнее».

**4. Изменения законов — всем подписчикам, не только ИИ-тарифу.** Сейчас это привязано к ИИ-тарифу. Решать тебе, но по правилу Д3 «держать порядок» — это ядро подписки.

## Что для этого строить (по шагам, каждый — отдельно)

1. Таблица уведомлений компании (что, когда, прочитано) + запись туда из уже существующих трёх скриптов. Push продолжает работать как есть.
2. Экран «Уведомления» в приложении + счётчик непрочитанных.
3. У `law_change_notices` — варианты текста с условиями вместо одного текста; выбор варианта по данным компании.
4. В админке — поля для вариантов при публикации изменения.
5. Публичная лента «Что изменилось в законах» на сайте (Д6) — из тех же записей, но общий текст без «вас».

## Что нужно от тебя

2. Изменения законов — всем подписчикам или только ИИ-тарифу?
3. Нужен ли дубль уведомлений на почту / в Telegram — или пока только раздел + push?
