# Матрица «ниша → модули ЛК» — накопительный черновик

Рабочий документ Фазы A (A1) плана `replicated-cooking-rainbow.md`. Ничего
отсюда не встроено в код/поведение продукта — `NICHE_EXTRA_MODULES` в
`backend/src/modules/security/security.routes.js` пока умеет только
ДОБАВЛЯТЬ модуль (`cleaning_basic → leads`), сокрытие не реализовано. Этот
файл — черновая рабочая версия, которая уточняется по одной нише за раз
(так же, как контент ниши «Общепит» потребовал отдельного research-прохода,
а не решался за один разговор). Статус каждой строки ниже — предположение,
не решение, пока явно не помечено иначе.

## Универсальный слой (решено 29.08.2026, не требует пересмотра по нишам)

Не завязаны на модель услуги, работают одинаково для любого бизнеса:
**security, document-templates, finance, ai-assistant, knowledge, feedback**.

## Визиты (решено 29.08.2026)

Скрыть только для Общепита (`cafe_basic`) — нет модели «визит к
конкретному мастеру» (точки продаж, не запись на услугу). Для всех
остальных ниш — оставить, включая Фитнес (владелец подтвердил: у
фитнеса есть персональные тренировки — это тоже «визит к мастеру»).

## Остальные три модуля — черновик по нише, требует разбора по одной

Чек-листы (чек-лист смены и отметки выполнения мастерами), Расходники
(склад расходных материалов, приход/списание/остаток), Клиенты (база
клиентов, история обращений).

## Процесс закрытия каждой строки

Тот же принцип, что и для контента ниш (см. Фазу B плана): разговор с
владельцем по конкретной нише → фиксация решения здесь с датой → перенос
в код (`NICHE_EXTRA_MODULES`/аналог) только после того, как разобрана
хотя бы одна ниша полностью, а не по одному полю за раз.
