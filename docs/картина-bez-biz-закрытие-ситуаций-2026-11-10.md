# Картина продукта Без.Биз — «Закрытие ситуаций»

Дата: 10.11.2026  
Для: сессия/агент, который дорабатывает Без.Биз  
Статус: продуктовая картина владельца. Срез героя S1 в коде — 10.11.2026 (ветка `cursor/simplify-bez-biz-entry`: витрина на главной, `/cases`, разовый checkout → папка эпизода).  
**11.11.2026:** лендинг `landing/index.html` переведён на витрину ситуаций; каталог в кабинете упорядочен; продукт уводим в фон как «завершённый срез» (не полный каталог всех веток).

Связь: `docs/упрощение-bez-biz-2026-11-09.md`, `docs/сценарии-предприниматель-2026-11-09.md`, `docs/оффер-разово-шаблоны-2026-11-09.md`, прототип `/cases`, тон `CLAUDE.md`.

---

## 1) В чём проблема сейчас

Как выглядит продукт сегодня для человека: тест → индекс/дыры → кабинет со вкладками → подписка / шаблоны.

Почему не покупают:
- это ощущается как **ещё один SaaS, в котором надо жить**;
- советы уже бесплатны в ChatGPT;
- шаблоны кажутся «скачаю где угодно»;
- нет единицы покупки вида «пришёл с сюжетом — ушёл с закрытым результатом».

Нужна **новая форма**, не классический SaaS и не чат.

---

## 2) Суть продукта одной фразой

**Без.Биз — не сервис, в котором надо жить. Это место, где владелец студии закрывает конкретную жизненную ситуацию: план + готовые бумаги (+ партнер при необходимости).**

Снаружи: магазин закрытий ситуаций.  
Внутри (движок на вырост): субъект → обязательства → шаги → proof → напоминание по желанию.  
Долгосрочно этот движок — клин в инфраструктуру «сжатия законов/разрешений/запретов в действия», но **сейчас не обещать инфраструктуру человеку**.

---

## 3) Что это НЕ

- Не кабинет «веди бизнес тут каждый день».
- Не чат с ИИ на главной.
- Не «защитим от штрафов» / гарантия проверки.
- Не обязательная подписка как главный оффер.
- Не CRM записи клиентов.
- Не бесплатный LLM на каждом шаге (правила + контент; ИИ позже и платно/лимитированно).

---

## 4) Единица ценности

**Эпизод = «Закрытие ситуации».**

Примеры ситуаций (человеческий язык):
1. Хочу принимать оплату картой / завести кассу (ветка S1 и рядом S2).
2. Навести порядок / боюсь проверки (тест + шаги + журналы).
3. Открываю ИП / студию с нуля.
4. Нанимаю первого мастера.
5. Нужны бумаги: оферта, согласия, политика.
6. Кончились журналы / нужна допечатка.
7. Когда платить патент / взносы / ЭЦП (коротко → даты).

Человек платит **за закрытие выбранного эпизода**, не за «доступ к платформе».

---

## 5) Картина пользовательского пути

```text
Вход: «Что у вас происходит?» (каталог ситуаций)
  → 5–8 коротких ответов
    → План: 5–12 шагов по порядку (бесплатно)
      → Кнопка: «Закрыть эту ситуацию» (разово деньги)
        → Папка эпизода: скачано / отмечено / что осталось
          → По желанию: одна дата в напоминания (не обязательно)
```

Критерий: владелец в ситуации открывает каталог **раньше**, чем идёт в общий чат с ИИ.

---

## 6) Как должны выглядеть экраны

### 6.1. Главный вход (витрина)

Не дашборд метрик и не «41 дело».

Показать:
- заголовок уровня: «Что у вас происходит?» / «Какую ситуацию закрыть?»
- 6–8 крупных карточек ситуаций человеческим языком
- мелко: «Уже есть папки эпизодов» (если были оплаты)

Спрятать с первого экрана:
- давление подписки
- ленту законов
- простыню онбординга
- чат
- финансы/операционку чужой студии (не герой этого продукта)

Опора: идея simple home + сделать каталог ситуаций **главным**, не вторичным `/cases`.

### 6.2. Экран ситуации (квиз)

- 5–8 вопросов, короткие варианты
- без канцелярита и запугивания
- в конце — «Ваш план» списком шагов: что сделать / зачем коротко / куда

У каждого шага по возможности:
- статус уверенности: ок / проверить / пробел (как в сценариях)
- действие: инструкция | скачать бумагу | партнёр | отметить сделанным

### 6.3. Экран покупки закрытия

Одна понятная покупка, например:
- **Пакет закрытия ситуации** — бумаги/журналы/шаблоны, нужные именно этому плану
- опционально: комбо с PDF-заключением (если ситуация «дыры/порядок»)
- опционально: «человек/партнёр разберёт» для сложных веток (патент/касса) — без обещания «оформим за вас» без партнёра

Текст в тоне CLAUDE.md:
- честно: не юрконсультация и не гарантия проверки
- не писать «защитим от штрафов»
- не требовать подписку, чтобы скачать пакет закрытия

### 6.4. Папка эпизода (после оплаты / после плана)

- название ситуации + дата
- список шагов с галочками
- файлы скачивания
- блок «осталось» только по этой ситуации
- без принуждения жить в приложении

### 6.5. Вторичное (не витрина)

- Мои сроки — только если человек сам оставил даты
- Старый кабинет безопасности / тест — доступны как ситуации или из «ещё»
- Подписка — тихо: «обновления документов/сроков», не герой

---

## 7) Деньги (модель)

| Слой | Что | Деньги |
|---|---|---|
| Вход + план | Каталог + квиз + шаги | Бесплатно |
| Закрытие эпизода | Бумаги/журналы/нужные шаблоны под ситуацию | Разово |
| Усиление | Заключение PDF / партнёр | Разово |
| Повтор | Новая ситуация или допечатка журналов | Снова разово |
| Подписка | Только после ценности, тихо | Не холодный оффер |

Главный KPI касаний: довести до **оплаты закрытия ситуации**, не до «зарегистрировался в кабинете».

## 9) Минимальный срез на ближайшие 1–2 недели

Цель: одна герой-ситуация продаётся end-to-end.

Рекомендуемый герой (на выбор владельца, по умолчанию):
- **A:** «Хочу карту / кассу / патент» (S1) — острый жизненный сюжет  
- **B:** «Навести порядок / подготовка» — тест → шаги → пакет журналов/шаблонов  

Сделать:
1. Главный вход = каталог (хотя бы 4–6 карточек; рабочие — 1–2).
2. Одна ветка полностью: квиз → план → экран «Закрыть ситуацию» → выдача файлов/папка.
3. Подписку и чат убрать с этого пути.
4. Текст касаний/оффера говорить языком ситуации, не языком «зайдите в личный кабинет».

Не делать в этом срезе:
- новый чат-бот
- «инфраструктура для всей РФ» в UI
- новые вопросы в тест безопасности без отдельного решения владельца
- Релокант / семья / другие продукты

---

## 10) Тон и юридические рамки

- Не обещать гарантию результата проверки и «защиту от штрафов».
- Обещать: понятный порядок шагов и готовые бумаги под ситуацию.
- Шаги с неявной нормой помечать как требующие проверки / партнёра.
- Диагностика/план бесплатно остаются честными независимо от покупки.

---

## 11) Критерий «мы попали в новую форму»

Человек после касания понимает:
«Мне не надо осваивать программу. Я выбираю свою ситуацию и могу её закрыть.»

Факт-проверка:
- с первого экрана не торчит SaaS-кабинет;
- есть путь до разовой оплаты без подписки;
- после оплаты есть ощущение «эпизод закрыт / бумаги на руках», а не «теперь ведите аккаунт».
