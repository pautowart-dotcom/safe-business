# Движок бизнес-статуса и налогов — второе ядро продукта

_Реализовано за сессии 27–28.08.2026, все 4 фазы в проде. Этот документ фиксирует итоговую
архитектуру — не исходный план (`.claude/plans/sprightly-greeting-parrot.md`), а то, что реально
построено, с решениями, принятыми по ходу реализации._

## Зачем

Первый конкретный кейс инфраструктурного ядра, на котором строится остальной продукт (карта
фронтов, раздел 03а, «второе ядро» после самого теста безопасности): вести владельца через смену
юридического статуса бизнеса — сначала переход самозанятый→ИП (триггер по выручке/сотрудникам),
плюс региональный патент и рекомендатель системы налогообложения. Паттерн задуман обобщённым — под
будущие переходы (ИП→ООО, наём первого сотрудника, закрытие бизнеса) не нужна переархитектура,
только новый контент-файл и новый evaluator.

## Модель данных (миграция 0105)

- `companies.legal_form` (`self_employed`/`ip`/`ooo`, nullable, без бэкфилла угадыванием — NULL до
  реактивного заполнения).
- `companies.region_code` / `leads.region_code` — код субъекта РФ (2 цифры, ФНС/Конституция), FK на
  `regions`.
- `regions` — сид всех 89 субъектов РФ (сверено по Wikipedia 28.08.2026).
- `patent_rates` — регион × ниша × год × тариф, конвенция ревью контента (`status`/`reviewedBy`/
  `reviewedAt`/`lawReference`/`sourceUrl`) прямо в колонках таблицы, не в JS-файле — это данные, не
  редакторский контент.
- `business_status_transitions` — состояние конкретного перехода конкретной компании (многонедельный
  процесс с памятью прогресса), отдельно от `deadlines`/`registerAction` (просто пересчитываемое
  уведомление без памяти). `transition_key` CHECK пока только на `self_employed_to_ip`, расширяется
  новой миграцией по мере добавления переходов.
- `tax_regime` CHECK расширен значением `'self_employed'` (НПД) — раньше самозанятости не было
  вообще в этом списке.

## Контент-модуль (паттерн для будущих переходов)

`backend/src/modules/business-status/content/repository.js` — та же конвенция, что у
`document-templates`/`security`: один файл на переход, доступ только через репозиторий. Сейчас
заполнен один переход — `transitions/selfEmployedToIp.js` (шаги регистрации ИП переиспользованы из
уже проверенного `roadmap/content/registrationSteps.js`, два новых шага про УСН/снятие с учёта НПД
помечены `status: 'draft'` до юридической проверки). Следующий переход добавляется новым файлом +
записью в реестре, без изменения остального кода.

## Триггер (Фаза 1)

`backend/src/scripts/businessStatusTriggers.js`, cron 6:00 МСК. Реестр `{key, evaluate, title}` —
сейчас один evaluator. Для `self_employed_to_ip`:
- `has_employees=true` → жёсткое правило (ст. 4 422-ФЗ), немедленный триггер;
- скользящая 12-месячная выручка (`computeTrailingRevenue()`) ≥ 80% лимита НПД (2 400 000 ₽) →
  «приближается»; ≥ 100% → «превышен». Порог 80% — решение по умолчанию, не запрошено владельцем
  явным числом, легко поменять константой `APPROACHING_THRESHOLD_RATIO`.

`dismissed` карточка всплывает снова только если новая причина СТРОГО серьёзнее прежней (порядок:
`revenue_approaching` < `revenue_exceeded` < `has_employees`) — решение владельца 28.08.2026.
Категория дедлайна/действия — `'tax'` (переиспользована существующая, `'legal'` не возвращали).
Живой триггер — только платным компаниям (`isSubscriptionActive`); для `legal_form IS NULL`
отдельное некатегоричное уведомление «уточните форму бизнеса».

Универсальная страница перехода — `frontend/src/pages/BusinessStatusTransition.jsx`, один экран на
любой `transition_key`, прогресс по шагам в `steps_state` (JSONB, ключ — индекс шага).

## Региональный патент (Фаза 2)

`backend/src/core/patentRates.js` → `getPatentRate()`, три явных статуса (`found`/`unknown_region`/
`unknown_tier`) — никогда не угаданное число. **Заполняется реактивно** — решение владельца
28.08.2026: строка добавляется только когда регион+ниша+год реально понадобились платящей компании,
не заранее на все 89×9 возможных комбинаций (это нереально поддерживать соло-фаундеру, и данные
протухают ежегодно). Админка `patent-rates` (`admin-frontend/src/pages/PatentRates.jsx`) — форма
«добавить одну строку», без CSV-импорта: при таком темпе заполнения он не нужен.

Автоподстановка в ручной ввод патента (`my-deadlines.routes.js`) — только если у компании известны
регион и ровно одна ниша (при нескольких нишах не гадаем).

Анонимная воронка (`landing/start.html`) получила статичный неперсонализированный абзац «возможно,
понадобится ИП» рядом с рекомендацией самозанятости — крючок на подписку, не сама услуга (бесплатно
остаётся только разовая рекомендация юрформы, как и раньше).

## Рекомендатель режима (Фаза 3)

`backend/src/core/taxRegimeRecommender.js` — сравнение по реальным `finance_entries`/
`expense_entries` компании с начала текущего года (не прогноз на весь год, честная YTD-оценка):
- УСН «Доходы» (6%) — с вычетом уплаченных страховых взносов (без сотрудников — до нуля, с
  сотрудниками — не более половины, п. 3.1 ст. 346.21 НК РФ);
- УСН «Доходы−Расходы» (15%) — с минимальным налогом 1% от выручки (п. 6 ст. 346.18 НК РФ);
- Патент — через `getPatentRate()`;
- ОСН — **не считается**, только статичное пояснение («обычно невыгоден без НДС-контрагентов») —
  подтверждено владельцем 28.08.2026, отдельный крупный движок ради ниши, которая целевой аудитории
  почти никогда не нужна.

Дедлайны переключения через существующий `registerDeadline()`: уведомление на УСН — до 31 декабря
(ст. 346.13 НК РФ); заявление на патент — за 10 рабочих дней до старта, рабочие дни считаются
упрощённо (только выходные, без праздничного календаря РФ — решение владельца для v1,
`subtractWorkingDaysUTC()`).

## Числа, которые нужно проверять КАЖДЫЙ год

Это главная новая зона ответственности `law-compliance-monitor` от этого движка (см. обновлённый
`law-compliance-monitor.md`) — в отличие от лимита НПД (2 400 000 ₽, стабилен с 422-ФЗ) и порога
допвзноса (300 000 ₽, стабилен), следующие цифры меняются ежегодно и по своей природе рискуют
незаметно устареть в январе:

- `FIXED_INSURANCE_CONTRIBUTION_RUB` (`taxRegimeRecommender.js`) — фиксированные страховые взносы
  ИП «за себя», на 2026 год 57 390 ₽ (сверено WebSearch 28.08.2026).
- Даты в `taxDeadlines.js` — при разработке этого движка нашлась и исправлена реальная ошибка:
  `insurance_fixed` показывал срок 31 декабря вместо верного 28 декабря (реформа ЕНП 2023 года) —
  соседние даты (УСН-авансы) поправили 04.08.2026, этот слот тогда пропустили. Урок: точечные правки
  дат нужно перепроверять по всему файлу, не только по изменённой строке.
- Все строки `patent_rates` — региональные законы о патенте переиздаются на каждый год.

## Известные ограничения (сознательные, не забытые)

- `finance_entries`/`expense_entries` не сверены с банком — все расчёты (триггер, резерв, рекомендатель)
  честны настолько, насколько компания сама ведёт учёт в приложении.
- Патент покрыт для небольшого меньшинства регионов первое время — это ожидаемо при реактивном
  заполнении, не баг.
- ОСН — принципиально не считается (см. выше).
- Рабочие дни для патента — упрощённо, без праздничного календаря РФ.
- Стабы будущих переходов (ИП→ООО, наём первого сотрудника, закрытие бизнеса,
  самостоятельное переключение режима) сознательно не заведены — паттерн (репозиторий + реестр
  evaluator'ов + универсальная страница) готов принять их без переархитектуры, когда понадобятся.
