## Что сделано за сессию

### Куча точечных багов (найдены с реального телефона)
- **"Нет выручки за сегодня"** — реальный баг с часовым поясом: сервер в
  UTC, все студии в Москве. Дата "сегодня" в нескольких местах бэкенда и
  фронта считалась по UTC/серверному времени, а не по Москве — с полуночи
  примерно до 15:00 по Москве дашборд мог показывать вчерашний день.
  Починено везде: `backend/src/utils/moscowDate.js` +
  `frontend/src/utils/localDate.js`, плюс таймзона Postgres-сессии
  (`db/pool.js`, через startup-параметр `options`, не через отдельный
  `SET TIME ZONE` — та версия ловила deprecation-warning в pg). Заодно
  нашли и починили **настоящий** баг (не только полуночный): в
  `Finance.jsx` начало месяца/недели считалось через `toISOString()` —
  при часовом поясе UTC+3 это всегда сдвигало дату на день назад.
- **Расходники на форме визита** — было ~20 отдельных кнопок под каждый
  цвет геля с нормой на клиента (стена кнопок). Свёрнуто в один выпадающий
  список, количество подставляется само при выборе.
- **Мастер теперь может добавлять новые позиции склада** (раньше только
  owner/admin) — редактирование/удаление по-прежнему только им.
- **Скидка на визите** — добавлена альтернатива в рублях (не только %),
  `discount_fixed_amount` в схеме, взаимоисключающе с процентом.

### Увольнение/удаление
- **Мастера/админа теперь "увольняют" (деактивация), а не удаляют** —
  раньше упиралось в `ON DELETE RESTRICT` у visits.master_membership_id.
  Заодно закрыта дыра: уволенный сохранял доступ до истечения токена (до
  30 дней) — теперь `active` проверяется на каждый запрос.
  **Осознанный пробел**: кнопки "Восстановить" в интерфейсе нет.
- **Повторное приглашение уволенного** (тот же email) теперь реактивирует
  старую запись (с ролью/филиалом/% из нового приглашения), а не падает на
  дубле/уникальном индексе.
- **Удаление клиента с визитами** — та же RESTRICT-ловушка, что и у
  мастера, но раньше не обработана: падало сырой 500. Починено по образцу
  расходников — понятная ошибка вместо технической.

### Фотоотчёты (новая функция)
Отдельная страница "Фотоотчёты" (Ещё → Фотоотчёты, видна и владельцу/
админу, и мастеру на своих визитах) — лента визитов с фото до/после,
полноэкранный просмотр по тапу. Была найдена и починена серьёзная проблема
на iOS: `position: fixed` внутри контейнера с
`-webkit-overflow-scrolling: touch` (Layout.jsx) на iOS привязывается к
самому контейнеру, а не к экрану — шапка оставалась кликабельной поверх
просмотра фото, а долистать до следующих фото было некуда. Починено
React-порталом прямо в `document.body`.

### Pull-to-refresh — докатан почти везде
Был подключён только на 3 страницах (Клиенты/Финансы/Визиты) — не
осознанное решение, просто не довели до конца. Добавлен на обе Главные,
Чек-листы, Базу знаний, Команду, Обратную связь, Дедлайны, Поддержку,
Склад, Подписку, Мои сроки, все вкладки Журналов (хоть раздел и заморожен,
код остался). **Осознанно не трогали**: `Security.jsx` — сложная
механика вкладок/визарда, не хотели ломать не глядя.

### ЮKassa — боевой режим
Ключи в `.env`, webhook указан и настроен (проверены нужные события:
`payment.succeeded`/`payment.waiting_for_capture`/`payment.canceled`
достаточно, `refund.succeeded` не критичен, `payment_method.active` не
нужен). **По словам владельца — всё подключено с его стороны.** Первый
реальный платёж ещё не проведён — решили закрыть вопрос, когда придут
первые настоящие оплаты (это по его словам ожидаемо потребует донастройки).

### Цена подписки — решение
Обсуждали идею "первый месяц бесплатно + 1490₽ вместо 1990₽". **Решили
оставить 1990₽ как есть** — платящих клиентов пока 0, "дорого" было личным
предчувствием владельца без реального фидбэка. План: сначала вынести
продукт в чат мастеров по текущей цене, посмотреть на реальные возражения,
и только тогда возвращаться к вопросу цены предметно.

### Раздел "Журналы" — заморожен целиком
Решение владельца: заморозить УФ-лампу/Инструктаж/Дезсредства/Печатные
бланки **до легализации электронных журналов**. Убрано из меню у всех
ролей, заблокировано на бэкенде (403 на прямой вызов API — защита от
старой версии фронта в кэше). **Публичная проверка QR** на уже выданных
бумажных бланках (`/j/:token`) **не тронута** — работает для физических
книг, которые уже на руках у студий. Почищены все дангл-ссылки на
"Журналы" в онбординге, "Мои сроки", подсказке склада, настройках
уведомлений. Код не удалён — включить обратно можно откатом коммита
`30fe9c9`.

### Главный экран владельца — редизайн
Отдельное ТЗ: строгая иерархия важности вместо набора произвольных карточек,
никакого AI-слоя/скоринга. Порядок:
1. **Критические действия** — просрочено/без даты по документам (медкнижки,
   огнетушитель, ЭЦП, патент, СОУТ, дезинфекция, отходы — категории
   staff/premises/documents из уже существующей таблицы дедлайнов) +
   проблема с оплатой подписки. **Рендерится только когда есть что
   показать** — после фидбэка владельца ("пустое 'критических действий
   нет' каждый день — просто шум") блок скрывается совсем, если нечего
   показывать, как уже работает "Центр действий" ниже.
2. **Статус документов** — просто "X в порядке / Y требуют внимания", без
   индекса.
3. **Рекомендации** — простые правила по датам ("через N дн. истекает X —
   пора продлить"), вынесены в отдельный модуль
   `frontend/src/utils/dashboardRecommendations.js` с чистым интерфейсом
   (вход: дедлайны+подписка, выход: список) — точка замены на настоящую
   модель в будущем без переписывания экрана.
4. Всё остальное — то, что раньше было единственным содержимым экрана
   (сводка смены, выручка, заметки, диагностика безопасности, команда,
   события).

Блок с рутинным статусом подписки **убран с главного экрана совсем** (по
просьбе владельца) — статус остался на `/subscription`, а проблема с
оплатой по-прежнему всплывает в критических действиях, если есть.

Экран администратора и мастера **не тронуты** — owner теперь отдельная
ветка компонента (`OwnerDashboard` в `Dashboard.jsx`), а не общая с admin.

Проверено визуально (мок-бэкенд + Playwright, см. выше про окружение) в
обоих состояниях — "есть критика" и "всё в порядке".
